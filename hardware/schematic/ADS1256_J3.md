# ADS1256 connection via J3

This document describes the tested connection of an external ADS1256
24-bit ADC module to the Multi-Channel DataLogger through the existing
J3 Sensor Input Connector.

## Connection

| J3 / Raspberry Pi Pico | ADS1256 | Function |
|---|---|---|
| 5V | VCC | Module power supply |
| GND | GND | Common ground |
| GP2 | SCLK | SPI clock |
| GP3 | DIN | SPI MOSI |
| GP4 | DOUT | SPI MISO |
| GP5 | CS | Chip select |
| GP26 | DRDY | Data ready |
| GP27 | RST | Hardware reset |
| 3V3 | PDWN | Keeps ADS1256 active |

## Unused J3 signal

GP22 is intentionally not used for the ADS1256.

GP22 is used by the existing 1-Wire bus and has a 4.7 kOhm pull-up
resistor to 3.3 V.

## ADS1256 module notes

- ADS1256 VCC is powered from the J3 5V output.
- PDWN is tied to J3 3V3 and is not controlled by firmware.
- The module pin marked `2.5V` is not connected.
- SPI communication is implemented in software because the selected
  J3 GPIO combination does not form a complete RP2040 hardware SPI bus.

## Verified communication

The connection was tested with MicroPython.

Register readout:

```text
STATUS = 0x30
MUX    = 0x01
ADCON  = 0x20
DRATE  = 0xF0
IO     = 0xE1

CHIP ID = 0x3
```
The returned CHIP ID `0x3` confirms successful communication with the ADS1256.

## Final pin assignment
```text
J3                  ADS1256
--------------------------------
5V       ---------> VCC
GND      ---------> GND
GP2      ---------> SCLK
GP3      ---------> DIN
GP4      <--------- DOUT
GP5      ---------> CS
GP26     <--------- DRDY
GP27     ---------> RST
3V3      ---------> PDWN
GP22                not used
2.5V                not connected
```

## Reference-voltage troubleshooting

Earlier troubleshooting found approximately 5.064 V at the module connector
marked `2.5V`. PCB continuity measurements showed that this point is also
connected to ADS1256 VREFP; VREFN is connected to GND. The SOIC-8 device at
the reference position was reported as marked `LM337LM`, with only pins
2 (supply), 4 (GND), and 6 (reference output) connected on the PCB.

The project discussion identified ADR03 in SOIC-8 as the replacement
candidate for the REF03 reference position. The latest diagnostic logs
record a working reference value of **2.503 V**. These logs establish the
test conditions below; they do not themselves record the fitted part number.
The earlier 5.064 V value must not be reused as the reference setting for
these measurements.

The module's `2.5V` connector remains unconnected to J3; this does not mean
that the reference is disconnected internally from the ADC.

## Measurement verification — 2026-10-16

Source: user-supplied diagnostic output in the project discussion
“Náhrada REF03 cez ADR03”.

Test settings and status:

- Reference value used by the diagnostic script: **VREF = 2.503 V**.
- **PGA = 1**.
- Hardware reset completed successfully.
- Register readback matched the reset values shown above, including chip ID 3.
- **SELFCAL completed successfully**.
- Conversion-rate setting: **100 SPS**, with **DRATE = 0x82**.
- All eight channels were exercised. The 100 SPS value is the ADC rate
  setting, not a demonstrated rate of 100 complete eight-channel scans/s.

Values are copied from the diagnostic output. Peak-to-peak figures were
calculated by that script from its unrounded readings, so they can differ
slightly from subtraction of the displayed six-decimal endpoints.

In the preceding test, CH2 had a mean of 1.231913 V and peak-to-peak
variation of 855.2 µV. After the user improved the connections, CH2 measured
1.229630 V with 10.1 µV peak-to-peak variation. The earlier CH2 anomaly
was absent in the final run. This supports checking connection quality
before attributing that anomaly to the ADC.

The final channel means span 60 µV (CH0 minus CH6), and the recorded
within-channel peak-to-peak variation ranges from 4.8 to 12.5 µV.
These results demonstrate repeatability under the reported test conditions;
they do not establish absolute accuracy or performance over the full input
range without an independently characterized source.

## Firmware integration status

`firmware/main.py` now provides the manual source-code switch
`ADS1256_ENABLED` (default `True`). Set it to `False` and restart for the
original A1/A2 and B1–B4 inputs. Only the selected input configuration is
initialized, because both configurations share GP2–GP5 and GP26/GP27.
The switch does not change external wiring or power down the module.

The new `firmware/ads1256.py` driver reads AIN0–AIN7 against AINCOM,
using PGA=1, buffer off, VREF=2.503 V, DRATE=0x82, startup SELFCAL and
MUX/SYNC/WAKEUP sequencing. The logger writes AN0–AN7 in volts instead
of the original analog and digital columns. An incomplete or failed scan
is logged as empty channel cells, not as valid measurements.

See `firmware/README.md` for configuration, CSV formats, display behavior
and error handling. The existing encoder menu is unchanged. The module
was tested separately as documented above; the newly integrated firmware
still requires verification on Pico.
