# ADS1256 connection via J3

This document describes the tested connection of an external ADS1256
24-bit ADC module to the Multi-Channel DataLogger through the existing
J3 Sensor Input Connector.

## Connection

| J3 / Raspberry Pi Pico | ADS1256 | Function |
|---|---|---|
| 5V | VCC | Module power supply |
| GND | GND | Common ground |
| GP2 | SCLK | SPI clock |
| GP3 | DIN | SPI MOSI |
| GP4 | DOUT | SPI MISO |
| GP5 | CS | Chip select |
| GP26 | DRDY | Data ready |
| GP27 | RST | Hardware reset |
| 3V3 | PDWN | Keeps ADS1256 active |

## Unused J3 signal

GP22 is intentionally not used for the ADS1256.

GP22 is used by the existing 1-Wire bus and has a 4.7 kOhm pull-up
resistor to 3.3 V.

## ADS1256 module notes

- ADS1256 VCC is powered from the J3 5V output.
- PDWN is tied to J3 3V3 and is not controlled by firmware.
- The module pin marked `2.5V` is not connected.
- SPI communication is implemented in software because the selected
  J3 GPIO combination does not form a complete RP2040 hardware SPI bus.

## Verified communication

The connection was tested with MicroPython.

Register readout:

```text
STATUS = 0x30
MUX    = 0x01
ADCON  = 0x20
DRATE  = 0xF0
IO     = 0xE1

CHIP ID = 0x3
```
The returned CHIP ID `0x3` confirms successful communication with the ADS1256.

## Final pin assignment
```text
J3                  ADS1256
--------------------------------
5V       ---------> VCC
GND      ---------> GND
GP2      ---------> SCLK
GP3      ---------> DIN
GP4      <--------- DOUT
GP5      ---------> CS
GP26     <--------- DRDY
GP27     ---------> RST
3V3      ---------> PDWN
GP22                not used
2.5V                not connected
```

## Reference-voltage troubleshooting

Earlier troubleshooting found approximately 5.064 V at the module connector
marked `2.5V`. PCB continuity measurements showed that this point is also
connected to ADS1256 VREFP; VREFN is connected to GND. The SOIC-8 device at
the reference position was reported as marked `LM337LM`, with only pins
2 (supply), 4 (GND), and 6 (reference output) connected on the PCB.

The project discussion identified ADR03 in SOIC-8 as the replacement
candidate for the REF03 reference position. The latest diagnostic logs
record a working reference value of **2.503 V**. These logs establish the
test conditions below; they do not themselves record the fitted part number.
The earlier 5.064 V value must not be reused as the reference setting for
these measurements.

The module's `2.5V` connector remains unconnected to J3; this does not mean
that the reference is disconnected internally from the ADC.

## Firmware integration status

In PAUZA, select **ADS1256** with the rotary encoder and press to enter
its **On/Off** submenu. Rotate to choose and press to apply. On selects
AN0–AN7 and initializes/calibrates the module; Off restores A1/A2 and
B1–B4. Switching takes effect without restarting and is unavailable while
logging. Only the selected input configuration is initialized because both
configurations share GP2–GP5 and GP26/GP27. External J3 wiring must match
the selected mode; this menu does not physically disconnect or power down
the module. The choice is persisted in `input_mode.cfg`; missing or invalid
settings default to Off. Averaging, RAW and buffer choices are saved separately.

The new `firmware/ads1256.py` driver reads AIN0–AIN7 against AINCOM,
using PGA=1, selectable buffer (default off), VREF=2.503 V, DRATE=0x82, startup SELFCAL and
MUX/SYNC/WAKEUP sequencing. The logger writes AN0–AN7 in volts instead
of the original analog and digital columns with RAW Off. RAW On writes signed
integer codes in AN0_RAW–AN7_RAW without application averaging. An incomplete or failed scan
is logged as empty channel cells, not as valid measurements.

See `firmware/README.md` for configuration, CSV formats, display behavior
and error handling. The encoder menu now includes ADS1256 alongside
SyncRTC and TEST.

### Encoder-switch verification — 2026-10-19

The user confirmed that ADS1256 On/Off switching through the rotary
encoder works on the Pico. The integrated input-mode switch is therefore
hardware-tested. The earlier measurement results above remain the recorded
ADC test results; this confirmation adds no new accuracy, CSV, or fault
handling test results.

### Selectable averaging

The ADS1256 submenu now also contains **Vzorky** and **Spat**. In PAUZA,
Vzorky selects 1, 2, 4, 8, 16 or 32 fresh samples per channel for arithmetic
averaging. Collection is incremental across main-loop iterations; only
complete eight-channel averages are published to the OLED and CSV.
The ADC rate setting stays at 100 SPS. Larger counts slow output refresh;
see `firmware/README.md` for timing and CSV behavior. This addition has
host-side test coverage and still needs verification on Pico; the preceding
On/Off confirmation does not cover the new averaging submenu.


### RAW and impedance selection — 1.0.5-dev

The scrolling ADS1256 menu contains On, Off, Vzorky, RAW, Imp and Spat.
**Imp:Lo(5V)** disables BUFEN; **Imp:Hi(3V)** enables it. At the configured
PGA=1, 100 SPS and nominal 7.68 MHz ADC clock, typical effective input
impedance is 150 kΩ (Lo) or 40 MΩ (Hi). The 80 MΩ value applies only at
50 SPS or below. These are ADC parameters, not a measured module impedance.

With AINCOM=GND and AVDD=5 V, use approximately 0–5 V in Lo and 0–3 V
in Hi. In Hi, AINCOM and all used analog inputs must remain between AGND
and AVDD−2 V. At other supply voltages the Hi limit changes accordingly.
Neither RAW nor averaging extends the input voltage range. The measured
VREF=2.503 V and PGA=1 give a differential full scale of ±5.006 V; pin
voltage limits still apply. The 5V/3V label does not change the circuit.
See [TI datasheet, analog input buffer and table 3](https://www.ti.com/document-viewer/ADS1256/datasheet)
and the [firmware mode guide](../../firmware/README.md#raw-a-vstupný-buffer--105-dev)
for all mode combinations, CSV units, persistence and error recovery.
Earlier measurements in this document used buffer off; they do not validate
the full voltage range, high-impedance mode or raw-data recording.


### External resistor divider — 1.0.6-dev

The ADS1256 menu adds **Del:No / Del:1:K**, a shared setting for identical
external dividers on AN0–AN7. Rin connects the measured source to ANx;
Rgnd connects ANx to GND, with AINCOM tied to GND. The physical divider
must be fitted separately on every used channel. This setting does not
alter J3 wiring or the original A1/A2 input mode.

The conversion includes ADC loading: `Rd = Rgnd || Zadc`,
`K = 1 + Rin/Rd`, `Uin = Uadc * K`. Zadc is 150 kΩ in Lo and 40 MΩ in Hi
at the configured PGA=1 and 100 SPS. For Rgnd=10 kΩ and Rin=90 kΩ, K is
10.6 (Lo) or 10.00225 (Hi), giving nominal source ranges of 0–53 V or
0–30.00675 V at AVDD=5 V. These are model calculations, not tested hardware
voltage ratings; ADC pin limits and resistor/component ratings still apply.

RAW codes remain unscaled. With RAW Off, the display and CSV voltages
refer to the source before the divider. The configuration is persisted in
`ads_divider.cfg`; a new `adc_divider.py` module is required at deployment.
See the [divider instructions](../../firmware/README.md#vstupný-delič--106-dev)
for editor controls, nominal supply assumptions and validation steps.
The 1.0.6-dev bundle was deployed on Pico on 2026-11-05. File identity,
MicroPython syntax, pure divider calculations and startup were verified;
physical editor operation, divider recording and analog accuracy still need
verification. See the deployment record in firmware/README.md.
